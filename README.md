# ReaderC · 英文阅读伴侣

面向 **Zotero 9.0.x** 的英文 PDF 生词悬浮释义插件，当前版本 **0.2.0 开发预览版**。

生词下方显示浅绿色虚线，鼠标悬浮后立即出现中文释义（页面渲染后即在后台预取，无需等待网络）。悬停时按 **Backspace**、**Delete** 或**鼠标侧键**即可标记为熟词，虚线随即消失。熟词会持久保存，同一词元的常见屈折词形默认一起隐藏，支持撤销和恢复。

## 安装与使用

1. 安装包：[`dist/readerc-0.2.0-zotero9.xpi`](dist/readerc-0.2.0-zotero9.xpi)。
2. 在 Zotero 9 中打开 **工具 → 插件**，点击右上角**齿轮 → Install Add-on From File…**，选择上面的 `.xpi`。

   > Zotero 9 不扫描 `extensions/` 目录，把 xpi 拖进插件窗口或直接放进 profile 目录都不会被加载，必须走这个菜单安装。
3. **重启 Zotero**（插件仅在启动时加载）。
4. 打开有文本层的英文 PDF，将鼠标停在绿色虚线词上。
4. 在 **Zotero 设置 → ReaderC 英文词释** 中设置注释密度、释义来源和个人词表。新打开的 PDF 工具栏还提供“词释 ON/OFF”和“词释设置”。

如果 PDF 在安装前已经打开，关闭后重新打开可显示新增工具栏；后台会自动发现已有阅读页并启用悬浮释义。

### 阅读交互

- **悬浮**：约 120 毫秒后显示释义。释义在页面渲染后即于后台预取，命中缓存时几乎无等待。
- **标记熟词**：悬停出现释义后，按 **Backspace**（打字区，最顺手）、**Delete** 或**鼠标侧键**（后退/前进键）任一即可，无需先点击卡片。标记后虚线立即消失，左下角显示确认提示。
  > 侧键若无效，通常是鼠标驱动把侧键映射成了其他功能。
- **撤销**：点击短暂提示中的“撤销”；也可在设置中搜索该词，点击“恢复默认”。
- **补标生词**：选中英文词或短语，在 Zotero 选词弹窗中点击“词释 / 标生词”。支持最多四个词的短语。
- **加入生词**：卡片中的“加入生词”会使该词优先于词频规则显示。
- **Esc**：在卡片内关闭释义。
- **页面中直接按 Delete**：不触发 ReaderC 熟词操作，继续由 Zotero 处理。

## 释义来源：上下文翻译

释义由你配置的模型根据**目标词所在句子**选出一个最贴切的中文义项，只显示一个词义、不罗列多义。

内置 ECDICT 的 **363,525 个词条**和 **55,084 个词形关联**（来源及 MIT 许可见 [`addon/THIRD_PARTY_NOTICES.md`](addon/THIRD_PARTY_NOTICES.md)），用于**判断哪些词属于生词**（按词频排名）与还原词元，不用作释义来源。

在设置里填写：

- **接口地址**：支持 Chat Completions 请求格式的服务基础地址（如 `https://你的服务/v1`），或完整的 `/chat/completions` 地址。
- **模型名称**：由服务商或本地模型服务提供。
- **API Key**：按服务要求填写；无密钥的本地服务可以留空。

保存后点击“测试已保存的配置”。查询时只发送目标词和所在句子，不上传整篇 PDF。远程地址使用 HTTPS，本机地址允许 HTTP。Key 保存在 Zotero 密码存储中，不进入个人词表 JSON 或备份。

请求包含目标词在句子中的具体位置，并关闭推理（`reasoning_effort: none`）、限制输出长度以降延迟。同一句的多个生词合并为一次批量请求，页面渲染后即后台预取；接口失败、超时或格式不符时会逐词重试。模型释义仍可能出错。

## 初始生词判断

- 默认以 ECDICT 的 FRQ 词频排名为主、BNC 排名为后备，排名 3000 以后优先候选。
- 可切换为更多注释（1500）或较少注释（6000），这些参数不代表精确词汇量或考试水平。
- 明确标记的熟词和生词优先；未操作的注释不会被当作认识或不认识的训练标签。
- 单独的常见介词、功能词、全大写缩写不自动注释。
- 内置部分固定短语，例如 `in vitro`、`account for`，整体判断和释义。
- 同一词元默认每页只标记第一次出现，每页最多 100 处，可调整。
- 不依靠拼写相似性把所有派生词视为同一个词。

## 词表与数据

个人配置和词表保存在 Zotero 数据目录的 `readerc-state.json`，采用临时文件写入；写入失败时保留旧状态。插件卸载后保留词表。

设置中的“备份与导入词表”可生成 JSON 并复制保存，或粘贴 JSON 合并导入；不导出 Key 和接口配置。词元状态目前跨论文共用，不自动同步到其他设备。

## 自动更新

插件内置自动更新：Zotero 会定期读取仓库 `release` 标签下的 [`update.json`](update.json)，
发现更高版本时提示升级，无需手动下载。

发布新版本的流程：

```powershell
# 1. 修改 addon/manifest.json 的 version
# 2. 构建并生成更新清单
python tools/build.py
python tools/make-update-manifest.py --release
# 3. 上传清单（清单里的哈希对应刚构建的 XPI）
gh release upload release update.json --clobber
```

`update_hash` 必须与上传的 XPI 完全对应，所以务必先传 XPI 再传清单。

## 本地开发与预览

仅需 Node.js 和 Python，核心代码无第三方 JavaScript 运行时依赖。

```powershell
node --test tests/*.test.cjs
python tools/build.py
node tools/serve-demo.cjs
```

打开 `http://127.0.0.1:4173` 可以体验交互原型。演示使用同一套词库、标记、卡片和词表代码，数据存在浏览器本地，不访问 Zotero 文献库。它使用模拟 PDF 文本层，不能代替 Zotero 内的兼容性测试。

浏览器测试需要安装 Playwright 并提供 Chromium，可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向已安装的 Chrome：

```powershell
node tools/browser-test.cjs
```

结构、接口和验证说明见 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

## 当前验证范围与限制

已通过纯逻辑、模拟 Zotero 宿主及真实 HTTP 请求测试、Chromium 浏览器交互测试，并在**隔离的 Zotero 9.0.6 实例与实机环境中完成原生实测**：安装激活、PDF 打开、生词标记、悬浮上下文释义（预取后 0 ms）、Backspace / Delete / 鼠标侧键三种方式标记熟词、熟词隐藏、撤销、设置面板挂载、禁用/启用清理均通过。

原生验证使用 `.research/zotero9-smoke` 下的独立 profile 与数据目录，由 `tools/prepare-native-test.py` 与 `tools/native-command.py` 驱动测试控制器执行，不会访问真实文献库。

- 首版支持有文本层的 PDF；扫描件须先 OCR。
- PDF 的复杂阅读顺序、跨页句子、旋转文字以及特殊字体仍需要真实文档验证。
- 常见介词以词表过滤，未接入完整词性分析；例如具有多种词性的词可能漏标。
- 熟词目前按词元保存，尚不能区分同一个词的不同义项。
- 自动候选主要来自离线词库，未收录的专业词可通过选词补标。
- 初次加载约 34 MB 的未压缩词库（实机启动约 0.2 秒解析 363,525 词条）。
- 侧键依赖鼠标驱动映射；若侧键被映射为其他功能，请改用 Backspace 或 Delete。
